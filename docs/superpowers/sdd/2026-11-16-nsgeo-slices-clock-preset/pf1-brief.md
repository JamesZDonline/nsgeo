# PF-1: the "lost Time zero" estimate reads each line's raw record

## Why
Spec §4 (as approved): when a restored cube was saved with Time zero and its preset has since lost it, the range moves by the median first break "picked by Time zero's own rule at its default threshold". Task 3 picked it on the PREPARED lines (after the preset's other steps and the transform). Measured on the 10 real campus lines, median first break:
- prepared under [dewow]: −0.4764 ns (exact; equals the Time zero median line zero)
- prepared under [dewow, background_mean]: −0.3681 ns
- prepared under the author's real preset minus Time zero [dewow, background_mean, gain_agc, gain_curve]: −0.0433 ns — 2 samples late, nearly the whole −0.48 shift; the same under amp_square and none
- each line's RAW record (`first_break_ns(Radargram.from_profile(profile))`): −0.4764 on every line (exact)
So the gain steps, not the transform, move the pick. Time zero runs on the raw record in an ordinary preset (it is first). Task 3's real-data test used [dewow] only and missed this.

## Ruling (controller, ledger PF-1)
Pick each line's first break on its raw record, during preparation, and read the median of those.

## Changes
1. `packages/nsgeo-core/src/nsgeo/slices/binning.py`, `PreparedLine`: add `first_break_ns: float | None = None` — "the radar-clock time of the raw record's first arrival as Time zero picks it at its default threshold, or None for a record with no signal; read only to move a restored cube that was saved with Time zero onto the radar's clock (#162)". Keep the dataclass's other behaviour; Python 3.9-compatible annotations (`from __future__ import annotations` is already there or add it).
2. `packages/nsgeo-qgis/nsgeo_qgis/slices_engine.py`, the preparation worker (`_start_task`'s `work`): it already holds `radargram = Radargram.from_profile(profiles[0])` before running the stack. Compute the raw pick there (on the worker thread, so the main thread does no extra work) with the public Time zero step as `median_first_break` already does (`build_step("time_zero").apply(radargram).zero_ns`; a ValueError — no first arrival — gives None), and pass it as `first_break_ns=` to `PreparedLine`. The pick must use the raw `radargram`, never `result`.
3. `SliceEngine.median_first_break`: the median of the prepared lines' `first_break_ns` values that are not None; None with nothing prepared or no value. Remove the `amp_square` square-root special case and its docstring paragraph; the docstring says the pick is the raw record's, where Time zero runs in an ordinary preset, so neither the preset's other steps nor the transform move it. Drop the `threshold` parameter if nothing needs it (the worker uses the default 0.2); keep the signature `median_first_break(self) -> float | None` if you drop it, and update callers.
