# Deferred minors and rulings from the M12 task reviews

## Rulings
- Ruling (R-P1): The commit-trailer constraint is satisfied by subagents naming their own model; it is not handed to reviewers as binding and no fix round is sent over it — user's standing instruction — cost if wrong: none (cosmetic).
- Ruling (R-P2): `SliceEngine.__init__` gains keyword `on_grid_moved: Callable[[], None] | None = None` (also a public attribute). When set, `_on_grids_changed`'s fingerprint-changed branch calls `self.clear()` and then `on_grid_moved()` (guarded) instead of `set_source(self._choice)`; when None, M11 behaviour is byte-for-byte unchanged. SiteEngine builds its engines with it and re-queues the moved grid through its own serial `_dispatch_next` (only while active, never after `cancel()`). Owned by Task 3, with test `test_a_moved_grid_re_prepares_through_the_queue_never_alongside_another`. — Trap 1 is a spec-level invariant (one preparation at a time across all engines) and Ruling 1's peer check alone leaves this path open — cost if wrong: one more hook on M11's engine; a global gate inside SliceEngine would be the alternative, at much higher risk to M11's Rulings V/W.
- Ruling (R-P3): SiteEngine treats a grid whose `grid_axis` is None or has fewer than 2 levels as having no resolution (absent at every window), rather than constructing a Resolution that raises — `Resolution.__post_init__` requires t1 > t0 — cost if wrong: a grid overlapping the site range by exactly one level never shows (negligible).
- Ruling (R-P4): In Task 1's real split tests, all ten lines keep their natural world y = 0.25 + i·0.5 (as test_real_files.py places them); frame B's origin (0, 2.6) puts lines 5–9 at local y 0.15–2.15. "Shifted by 2.6" describes B-local coordinates; no extra shift is added — adding 2.6 would put lines 5–9 outside B's 13-cell frame — cost if wrong: none to behaviour; only the test geometry.
- Ruling (R-P5): Task 5 — while `scope() == "site"` the This-grid engine is never dispatched: on entering site scope the dock sets its engine's `on_grid_moved` to a handler that only marks it stale (R-P2 clears its lines), and resets it to None on leaving; `prepare()` (including `rebuild_source`'s auto-prepare) is deferred in site scope and runs on `set_scope("grid")`. Test `test_editing_a_grid_in_site_scope_never_overlaps_preparations`. — same invariant as R-P2 — cost if wrong: returning to This grid after a grid edit pays one preparation (~1 s), which M11 paid anyway.
- Ruling (T1-a): `Seam` becomes `@dataclass(frozen=True, eq=False)` against the plan's bare `frozen=True` — generated __eq__/__hash__ over ndarray fields raise, and a later cache comparison inside a Qt slot would be swallowed; the spec says nothing about Seam equality — cost if wrong: none (identity equality; interface unchanged).
- Ruling (T2-a): A bare grid-combo switch to a grid with no record remembers the preset showing and lines=None, as implemented — Ruling 5 names "a combo change", and recording what This grid actually prepared keeps both scopes showing that grid identically; the carried preset suits the common one-preset-everywhere case — cost if wrong: browsing grids marks the survey dirty and records an incidental preset; surface in the walkthrough.
- Ruling (T2-b): Restoring a saved cube through a user pick in the cube combo remembers the restored preset and lines for that grid; any automatic restore path remembers nothing — spec §4.2 "This grid scope reads and writes the same record" and a cube pick is a user choice — cost if wrong: switching back after a restore shows the cube's source rather than the one chosen before it.
- Ruling (T2-c): `set_site_view` keeps validating only `normalisation`; Task 5, building a SiteSource from site_view, falls back to the dock's default transform when the stored one is not offered — the brief names only normalisation and a stale string on disk must not break the scope switch — cost if wrong: none beyond one fallback branch.
- Ruling (T3-a): Step 5 mutant 5 (factors applied before fill) is an equivalent mutant — fill is a normalised weighted mean, so fill(a·v+b) = a·fill(v)+b to one float32 ulp; the test still pins a·fill(v)+b (dropping b is killed) — cost if wrong: none.
- Ruling (T3-b): The cross-engine dispatch gate uses a new read-only `SliceEngine.has_live_task` (`_running or bool(_pending)`), for own engines and `exclusive_with` peers; M11's `is_running` semantics stay unchanged. Closes the residual trap-1 hole where a cancel wait times out and clear()/dispose() force `_running` False while a task still runs on a worker. `_pending` empties in `finished`, which QgsTaskWrapper runs on termination including cancel-before-start — cost if wrong: a task whose finished never ran would stall the site queue (nothing prepares; no crash). Goes into Task 3's fix round with a timeout test.
- Ruling (T3-c): `choose_residency` estimates streaming cost per TRACE, not per line (same 16 ms frame budget and memory budget; constant derived from M11's 0.14 ms/line measurement and that measurement's trace count) — the bench shows the per-line estimate misjudges 3000-trace lines by ~3×, streaming a 46 ms/tick grid; spec §4.8 keeps residency "per grid and automatic, as M11 decides it", so fixing M11's estimate keeps its rule — cost if wrong: more grids hold cubes (14 MB per 50 m grid at 88 levels, ~4× at real sample counts), bounded per engine by DEFAULT_BUDGET_BYTES. Goes into Task 3's fix round; re-run the bench.
- Ruling (T3-d): Spec §4.2 requires per-grid progress ("preparing n of m"); SiteEngine wires each engine's `on_progress` and exposes `grid_progress(grid_id) -> tuple[int, int] | None` for Task 5; `grid_state` keeps the brief's values — the brief's "preparing" alone cannot render the spec's list — cost if wrong: one small accessor. Goes into Task 3's fix round.
- Ruling (T3-b, extended by review Important 1): the dispatch gate uses `has_live_task` over own engines, `exclusive_with` peers AND a set of retiring engines; `_drop_engine` cancels while the engine is still tracked, parks a still-live engine as retiring, and disposes it once its task has finished — cost if wrong: as T3-b.
- Ruling (T3-e): M11 concern 2 is fixed in this task, not filed — `finished`'s closed-site branch (generation still matching) is this request's own terminal edge, since any newer request bumps the generation first; it clears `_running` and wakes `_cancel_in_flight`'s confirm wait without applying results or reporting, so closing a site mid-preparation stops promptly and silently; the site-close test then asserts no errors (removes a test that dodged its hazard) — cost if wrong: `on_prepared` reaching a dock with no site open; the implementer checks the dock copes.
- Ruling (T3-f): review Minor 2 is treated as a brief miss and fixed now — on_changed must fire when a grid is dropped, becomes "no lines", or starts preparing; Task 5's list depends on it — cost if wrong: extra redraws of the list.
- Ruling (T3-g, the plan's Step 6 gate): Task 5's Step 4 fill-skipping drag degradation is NOT built — after T3-c the 10×50 m median slice_at is 67.9 ms, under the rule's threshold max(100 ms, 3 × 2.9 ms) = 100 ms, and the fill is 2.6 of 46 ms per streaming grid, so skipping it would buy nothing; instead Task 5 coalesces site-scope ticks (at most one per event-loop pass, the latest slider value wins), so a slow tick on a large streaming site never backs up, and the slice shown is always the full one — cost if wrong: a streaming 10×20 m site (~92 ms/tick) updates at ~11 fps while dragging.
- Ruling (T4-a): Task 5 disables "Export site GeoTIFF…" while any included grid is queued or preparing, and the export's success message names any included grid left out of the file (failed or no lines) — the file must not silently omit a grid the user included — cost if wrong: the user waits for preparation before exporting.
- Ruling (T4-b): Task 5's `export_site_geotiff` removes a partially written file when `export_site` raises, and adds the layer only on success — a failed export must not leave a GeoTIFF that reads as valid zeros — cost if wrong: none (M11's grid export keeps its behaviour).
- Ruling (T5-a): the walkthrough step "Tick it again. It returns without re-preparing" is reworded to "it re-prepares and returns" — Task 3's brief disposes a dropped grid's engine (releasing its memory), the spec never asks for instant re-tick, and keeping undrawn grids prepared would change the trap-1 module after its review — cost if wrong: one grid's preparation (~1 s per 24 lines) per re-tick; ask the user in the walkthrough.
- Ruling (T5-b): accept `SliceLayer.update`'s new extent/CRS sync after reloadData() (the brief said "unchanged behaviour") — the one preview layer is shared across scopes and the site lattice grows, so a layer keeping its creation extent/CRS would draw the site wrong; a no-op whenever extents agree — cost if wrong: a This-grid redraw re-sets an extent it already had.
