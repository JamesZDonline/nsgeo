# M21d: GPS placement for MALÅ and SEG-Y lines — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add data's GPS mode places MALÅ lines from their `.cor` and RadExplorer SEG-Y lines from the positions in their trace headers, as it places DZT lines from their DZG. Neither source has RTK, so a line without RTK is placed on its raw fixes, with a smoothing setting at import and per line afterwards. Each row says when its GPS and wheel lengths disagree.

**Architecture:**
- **Core, track:** `TrackPlacement` gains two defaulted fields, `anchor_on` and `smooth_m`. `track_from_log` picks the anchors.
- **Core, readers:** each format turns its own GPS source into the `DzgLog` that M17 already places. It does so through one new registry function, `read_gps`.
- **Plugin:** `gps_import` asks the registry instead of calling `dzg_for`. The GPS dialog gains a smoothing setting, and the Edit lines dialog a per-line one.

**Tech Stack:** Python 3.9+ numpy core (`packages/nsgeo-core`); QGIS plugin on QGIS 3.44 / PyQt5 and 4.2 / PyQt6 (`packages/nsgeo-qgis`); pytest.

**Spec:** `docs/superpowers/specs/2026-11-24-nsgeo-radar-formats-design.md`. Read in particular:
- §2: the `.cor` and SEG-Y geographic measurements of 2026-11-25.
- C10.
- §13 (GPS mode), §14 (`prefer`) and §15.
- **§16: the calls this plan makes.** Two of them revise M17a: lines without RTK are placed, and that reaches DZT lines too.

The GPS lines spec (M17) is the background for everything in `geometry/track.py` and `gps_import.py`.

## Review Focus

These are the inputs most likely to bite. Each is pinned by a test in the task that owns the code.

1. **RTK lines unchanged.**
   - A track with two or more RTK fixes gets `anchor_on="rtk"` from `track_from_log`, places exactly as before, and saves with no new key, at the old version.
   - With one RTK fix among many float fixes, the line now anchors on all of them. That is the M17 change §16 accepts. (Tasks 1 and 3)
2. **Smoothing:**
   - The window is in metres along the anchors' own path, and shrinks at the ends.
   - A straight track with alternating ±1 m cross-track jitter comes out within 0.1 m of the line with a 10 m window.
   - Smoothing 0 changes nothing, bit for bit.
   - Smoothing an RTK track is refused. (Task 1)
3. **`.cor` numbering.**
   - Its trace numbers count from 1, a DZG's from 0. A `.cor` whose last row names trace `LAST TRACE` reads, and one that names `LAST TRACE + 1` is refused.
   - On the real files, every fix's trace is within the line. (Task 2)
4. **SEG-Y repeats.**
   - Only the first trace of each run of equal positions is a fix, and only on traces whose little-endian flag is 1.
   - A synthetic file whose position changes every third trace gives a third as many fixes, at traces 0, 3, 6 and so on. (Task 2)
5. **Coordinates kept out of sight.**
   - No real-data test asserts or prints a position.
   - `repr` of a `NoGpsLog` and of every note holds no coordinate. (Tasks 2 and 3)
6. **A MALÅ pair in GPS mode.** Choosing `DAT_0001.rd3` and `.rd7` places one line, not two. (Task 3)
7. **The length check uses the thinned track**, not every fix: 2 m of DGPS jitter makes a raw path 10–50 % long by itself. On the real files the check flags all 18 SEG-Y lines and exactly DAT_0320, DAT_0321 and DAT_0323 of the MALÅ lines. (Tasks 2 and 3)
8. **Schema.** A site with a smoothed MALÅ line saves as the new version and reopens with its smoothing. A site with only RTK GPS lines saves as version 4, byte for byte as before. (Task 1)

**Interfaces:**
- **`class NoGpsLog(RadarFileError)`**: a line whose format has a GPS source, but this line has no log.
- **`RadarFormat.read_gps: Callable[[Path, RadarHeader, int], DzgLog] | None = None`.** Wired for each format:
  - **DZT:** `dzg_for`, then `read_dzg(dzg, n_traces)`. A missing DZG raises `NoGpsLog("no DZG beside it")`.
  - **MALÅ:** `companion(path, ".cor")`, then `mala.read_gps`. A missing `.cor` raises `NoGpsLog`.
  - **SEG-Y:** `segy.read_gps`.
  - **DT1:** `None`.

  Each goes through `_checked`.
- **`formats.read_gps(path, header, n_traces) -> DzgLog`** dispatches. A format whose `read_gps` is `None` raises `UnsupportedFormat(NO_GPS_FORMAT)`. Move the constant into `formats.py` and re-export it from `gps_import`, so the plugin's name keeps working.
- **`formats.gps_formats() -> tuple[RadarFormat, ...]`**: the formats with a GPS source, in registry order.
- **`mala.read_gps(path, header) -> DzgLog`** parses the `.cor`:
  - Tab-separated, ten columns: trace, date, `HH:MM:SS` time, latitude, `N`/`S`, longitude, `E`/`W`, altitude, unit, quality.
  - Each fix: `trace − 1`, `utc_s` from the time, latitude and longitude signed by hemisphere, `quality` as given, `alt_m` when the unit is `M`, and `n_sats`, `hdop` and `geoid_m` as `None`.
  - Errors per the copy. Rows must rise, and `1 ≤ trace ≤ header.n_traces`.
  - `bad_checksum = 0` and `unpaired = 0`.
- **`segy.read_gps(path, header) -> DzgLog`** reads the little-endian flag (227–228), longitude (229–232) and latitude (233–236) of every trace, through the same whole-file read `read_header` uses.
  - Fixes are emitted at the first trace of each run of equal positions, among traces whose flag is 1. Each has `quality = QUALITY_UNKNOWN` and no time or altitude.
  - With no flagged trace, raise `NoGpsLog("its traces carry no GPS positions")`.
- **`gps_length_note(log, to_xy, n_traces, header) -> str | None`.** Use the anchors `track_from_log` would choose. Thin them to positions at least 5 m apart along the track, keeping the last, then compare that length with `(last anchor trace − first anchor trace) / traces_per_metre`.
  - Return the copy's note when they are more than 20 % apart.
  - Return `None` when `traces_per_metre ≤ 0` or the thinned track is under 5 m.
  - It takes the projection the plugin passes, so the core stays free of pyproj.
- **Writers:**
  - `write_cor(path, rows)` takes `(trace, lat, lon, quality)` tuples and writes the real layout: CRLF line endings, `M` units, a fixed date and times one second apart.
  - `write_segy(…, positions=None)` takes an `(n_traces, 2)` array of (lon, lat) degrees. It writes them ×10^6 little-endian with the flag 1, and `None` writes the flag 0 everywhere.
